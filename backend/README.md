# backend — серверная часть

API на **FastAPI** и аналитическое ядро на **pandas**.

Подробный разбор устройства — в `README.md` в корне репозитория: там по
шагам объяснено, что делает каждый слой и как они связаны. Здесь только
то, что нужно для работы именно с этой папкой.

## Запуск

Обычный способ — из **корня** репозитория, вместе с базой данных:

```bash
docker compose up --build
```

## Команды внутри этой папки

```bash
pytest -q                      # тесты
alembic upgrade head           # накатить миграции
alembic revision --autogenerate -m "описание"
```

Зависимости ставятся группами: в контейнер API попадают только основные,
аналитика и ноутбуки — отдельно.

```bash
poetry install                              # только API
poetry install --extras "analytics notebooks"   # плюс pandas, scipy, Jupyter
```

## Слои

Запрос проходит их сверху вниз, и каждый знает только о следующем:

```
api/routers    принять запрос, вернуть ответ      (не знает про SQL и правила)
services       решить, можно ли и что произойдёт   (не знает про HTTP и SQL)
repositories   достать и сохранить данные          (не знает про правила)
models         таблицы базы
```

Отдельно стоит `analytics/` — ядро продукта. Оно не знает ни про HTTP, ни
про базу: на входе DataFrame, на выходе DataFrame или объект с результатом.
Поэтому его можно запускать в ноутбуке и тестировать на синтетике за секунды.

Быстрая проверка, что слои не перепутались:

| В файлах папки | Не должно встречаться |
|---|---|
| `api/routers/` | `select(`, `session`, `hash_password` |
| `services/` | `select(`, `from fastapi`, `HTTPException` |
| `repositories/` | бизнес-правила вида «чужое не показывать» |
| `core/` | импорты `User`, `Note` и любых других моделей |
| `analytics/` | `session`, `request`, `await` |
