# frontend — интерфейс продукта

Папка-заготовка. Код появится на фазе 5 (`ROADMAP.md`), а пока здесь
зафиксированы решения, чтобы не выбирать их заново в спешке.

## Стек

| Что | Чем | Почему именно так |
|---|---|---|
| Фреймворк | Next.js (App Router) + TypeScript | Работодатели смотрят именно на него; типы страхуют на стыке с API |
| Стили | Tailwind + shadcn/ui | Готовые компоненты приличного вида без своего дизайнера |
| Запросы | TanStack Query | Кеш, повторы и опрос статуса расчёта из коробки |
| Графики | Recharts | Простые графики; для тепловой карты когорт — ECharts |
| Клиент API | генерируется из OpenAPI | Бэкенд уже отдаёт схему — руками типы не пишем |

## Создание проекта

Выполняется один раз, из корня репозитория:

```bash
npx create-next-app@latest frontend --typescript --tailwind --app --eslint
cd frontend
npm install @tanstack/react-query recharts
npm install -D openapi-typescript
```

Генерация типов из живого API (бэкенд должен быть запущен):

```bash
npx openapi-typescript http://localhost:8000/openapi.json -o src/lib/api-types.ts
```

Эту команду стоит повесить в `package.json` скриптом и вызывать после
каждого изменения схем на бэкенде — тогда рассинхрон типов обнаружится
при сборке, а не у пользователя.

## Порядок работы над экранами

Не по алфавиту и не по сложности, а по пользе:

1. **демо-дашборд** — витрина проекта, его показывают в первую очередь;
2. **загрузка с сопоставлением колонок** — без неё продуктом не
   воспользоваться;
3. **прогресс расчёта** — иначе кажется, что сайт завис;
4. **обзор** с числом «деньги под риском»;
5. сегменты, когорты, таблица клиентов, карточка клиента;
6. **лендинг** — последним, когда есть что показывать на скриншотах.

## Две вещи, которые легко отложить и потом дорого исправлять

**Токен в httpOnly-cookie, а не в `localStorage`.** Мы работаем с чужими
клиентскими базами; токен в `localStorage` достаётся любым XSS. Это
потребует доработки бэкенда — там же пригодятся refresh-токены.

**Пустые состояния и состояния загрузки.** Именно они создают ощущение
законченного продукта. Дашборд с идеальной аналитикой, но с пустым белым
экраном во время расчёта выглядит сырым.
